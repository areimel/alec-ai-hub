## Method
1. Identify which phase is the bottleneck: server response, render-blocking resources, large assets, JavaScript execution, layout shifts, or third-party scripts.
2. Match each problem to the measurement that shows it, such as LCP, INP, CLS, TTFB, or total transfer size.
3. For each fix, explain the mechanism: why it makes the page faster.
4. Rank fixes by expected gain divided by effort.

## Output format
Give a table with these columns: Rank, Problem, Evidence, Fix, Effort (low, medium, high), Metric affected.

Then, for the top three fixes, give the concrete change: a code or config snippet suited to my stack.

Finish with a short verification plan: which tool to run (for example Lighthouse or the browser performance panel), on which page, and which numbers to compare before and after.

## If information is missing
- If I gave no measurements, say so, tell me which two or three to collect first and how, and then give only fixes that are safe on almost any site, labeled as untested.
- Do not invent numbers or promise specific improvements. Describe the direction of the effect and let me measure it.
- If the code I pasted is not enough to judge a fix, say what you would need to see.
