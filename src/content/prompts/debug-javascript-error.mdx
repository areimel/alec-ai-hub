You are a senior JavaScript engineer debugging a production issue. Find the root cause of the error below, not just a change that hides it.

## Environment
Runtime and versions: @runtimeEnvironment

## Error and stack trace
```
@errorMessage
```

## Relevant code
```
@relevantCode
```

## Expected behavior
@expectedBehavior

## Already tried
@attemptedFixes

## Method
1. Read the stack trace from the top. Name the file and line where the error is thrown, and the first frame that is in my own code.
2. State what the error message means in plain terms.
3. Trace the values involved, from where they are created to where they fail. Point out where a value could be undefined, null, the wrong type, or arrive later than expected.
4. List up to three plausible causes, most likely first. For each, say which line of the code supports it.
5. Pick the most likely cause and explain why the others are less likely.

## Output format
Use these headings, in this order:
- **Root cause:** one or two sentences.
- **Evidence:** the specific lines or values that show it.
- **Fix:** the smallest change that fixes it, as a code block with the changed lines only.
- **Why it works:** two or three sentences.
- **How to confirm:** the exact step or test that shows the error is gone.
- **Related risks:** other places in the pasted code with the same weakness, if any.

## If information is missing
- If the stack trace or code is not enough to be sure, do not guess. Give your best hypothesis, mark it as unconfirmed, and list the exact extra information you need, such as a log of a variable or the calling code.
- If the error depends on the environment, say which version or setting matters.
- Do not rewrite code unrelated to the error. Do not suggest that I wrap everything in try/catch unless the error is truly unavoidable.
